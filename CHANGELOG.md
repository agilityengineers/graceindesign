# Changelog

## Unreleased — consultation photo upload hardening
- **The consultation form's photo upload only stores real JPG, PNG, WebP or GIF files.** `/api/consult/upload` reads the file's first bytes to decide its type (`src/lib/image-signature.ts`) and names the stored file by that type, instead of trusting the type and extension the browser reports. Anything else (SVG, HTML, PDF…) is refused with "Please upload a JPG, PNG, WebP or GIF photo.", and the form now shows that message instead of silently dropping the file. Previously a renamed `.svg` could be stored and served from the site's own domain as `image/svg+xml`.
- `/api/media/leads/photos/*` checks the stored bytes the same way: anything that isn't one of those four types, including files stored before this change, downloads as `application/octet-stream` with `content-disposition: attachment`. Media responses carry `X-Content-Type-Options: nosniff` directly, and SVGs from the media library get a sandboxing Content-Security-Policy. `npm run test:image-signature` covers the signature checks.
