# Decisions

Choices made where the design handoff (`docs/handoff/README.md`) left something open, or where the owner's direction replaced the handoff's recommendation. Each entry says what was decided, why, and what it would take to change.

## Platform

1. **Replit instead of Vercel + Supabase.** The owner asked for the app to run in Replit production. The app uses Replit's built-in PostgreSQL (Neon-backed) through Drizzle ORM, Replit Object Storage for uploads, and an Autoscale deployment (`.replit`). Nothing is Replit-specific in the code: `DATABASE_URL`, `BASE_URL` and `REPLIT_OBJECT_STORAGE_BUCKET` are the only environment touch points, and uploads fall back to `./.data/uploads` when Object Storage is absent, so the same code runs on any Node host with Postgres.
2. **Own auth instead of Supabase Auth.** Invite-only magic links (`/login`), database-backed sessions, a signed `gid_session` cookie, and four roles (owner, editor, sales, social) plus an `isSuperAdmin` flag. Permission checks happen in server code (`src/lib/auth/session.ts`: `can()`, `requireArea()`, `requireOwner()`), which replaces the handoff's Row Level Security. Every admin page and server action calls `requireArea`, and every public endpoint is rate limited.
3. **SendGrid instead of Resend for email, Twilio for SMS** (owner's direction). Every outgoing message is written to the `outbox` table first and then delivered; without API keys the message stays in the outbox with status `logged` so the whole funnel is testable before credentials exist. Admin → Client ops → Outbox shows every message and lets you re-send.
4. **Scheduled work runs through `/api/cron/<job>` or `npm run cron -- <job>`.** Replit has no built-in cron for web deployments, so a Scheduled Deployment (or any external scheduler) calls the endpoint with `CRON_SECRET`. Jobs: reminders, rss, etsy, social, drips, webhooks, outbox, hubspot, all. Admin → Client ops → Scheduled jobs runs any job on demand and shows the run log.

## Call Flow Tracker (future architecture)

5. **Built now, switched on later.** The CFT integration points exist and are inert until secrets are set: an inbound signed webhook (`/api/webhooks/cft`, `X-CallFlow-Signature`), the Connected Apps SSO child contract (`/api/sso/launch`, `/api/master/users`, `/api/master/users/[id]`, `/api/master/sessions/revoke`, `/api/dashboard-metrics`), a `users.cft_user_id` link, a configurable CFT role → GID role map (`site_settings.cft_role_map`), and outbound HMAC-signed webhooks (`X-GID-Signature`) that CFT can subscribe to. See `ARCHITECTURE.md`.

## Content and media

6. **Block-based CMS with draft → preview → publish.** `pages` hold `page_blocks` whose `content` is live and `draft_content` is the working copy. `?preview=1` shows drafts only to signed-in team members. The block editor is a generic form generated from the block's JSON (text, long text, images with upload, lists, tuple rows, nested objects), which keeps every block type editable without one bespoke editor per block.
7. **Media slots.** Every photo the designs use is a named slot (`media://int.kitchen-windows`). A slot resolves to the uploaded file, then a self-hosted copy in `public/media/`, then the brand asset or stock URL, then a labelled placeholder. Replacing a slot in the media library updates every page that uses it.
8. **Magnific imagery.** 38 photos were generated with Magnific (Seedream 5 Pro) for the stock placeholder slots; their creation ids live in `src/lib/seed-data/media.ts` and `scripts/magnific-creations.json`. The build container could not reach Magnific's CDN, so the files are fetched with `npm run media:fetch` from the Replit workspace (or uploaded through the media library). Until then those slots show the prototype's stock URLs or a placeholder. "Generate with Magnific" in the media library uses the Freepik text-to-image API with `MAGNIFIC_API_KEY`.
9. **Custom pages render at `/p/<key>`.** Core pages keep their designed routes; pages created in the CMS get a route automatically without code changes.
10. **Etsy listings are read from the public listing page** (Open Graph metadata) because the shop has no API key yet. "Refresh from Etsy" and the `etsy` cron job keep title, price, photo and review count current. `ETSY_API_KEY` is reserved for a later switch to the official API.
    **10a. Products link to whichever store sells them; Amazon first.** The previous site's product page pointed at Amazon, so each listing records a `retailer` (Amazon, Etsy, other) instead of assuming Etsy. Details are still read from the public listing page (Open Graph plus Amazon's own markup); Amazon answers automated requests inconsistently, so every field is editable and the scheduled refresh never overwrites a title, description or uploaded photo. Amazon links carry `rel="sponsored"` in case they are affiliate links, and the page's `disclosure` field holds the affiliate note if one is needed. The `etsy_url` column keeps its name (the schema field is `url`): renaming it would make Drizzle's generator ask an interactive rename question and touch production data for no visible gain. Rollout: `drizzle/0003_products_retailers.sql` + `npm run content:products` (`docs/products.md`). **Shopping cart = Amazon's own.** Amazon offers no embeddable cart, so "cart capability" is the Associates add-to-cart link (`/gp/aws/cart/add.html` with `AssociateTag`, `ASIN.n`, `Quantity.n`): a click puts the item(s) in the visitor's Amazon cart and checkout stays on Amazon, which keeps the site out of payments, inventory and returns. ASINs are read from the product link rather than stored. Live product data comes from the Product Advertising API 5 when its keys exist (signed in-house with Signature V4 to avoid an SDK dependency for one endpoint) and from the public page otherwise. Placing the shop "anywhere" is a CMS block (`product_shelf`) rather than a script embed, so it inherits the site's design and the admin's publish flow.
    **10b. Curated sections are shelves, not categories.** WELLness-Products (the bottom of Healthy Home Resources) needed a set of products the admin picks by hand without disturbing the AIP Products page or its category filters, so a listing carries `shelves` (`products.shelves`, registry in `src/lib/shelves.ts`) and a `product_shelf` block names the shelf it shows. One listing can sit on several shelves; the admin stocks a shelf from Admin → Products (new Amazon products go on WELLness-Products by default, one click takes them off), and an empty shelf hides its section instead of showing an empty heading.
11. **Posts accept HTML in the body.** A full WYSIWYG editor was out of scope; the body field takes HTML or plain text and RSS imports keep linking out to the source.

## Funnel and pipeline

12. **Availability is Eastern time.** All booking math (`etDate`, slot generation, reminders) uses `America/New_York`, matching the business. The seed also writes demo timestamps in Eastern time so "Today" reads correctly in the admin.
13. **Demo projects are earlier engagements, not conversions.** The seed links a project to a lead only when the lead is "Won" (Rosa Delgado), so the Leads board shows the same mix of stages as the prototype while the Project Pipeline still has five projects.
14. **Admins can delete and modify everything** (owner's requirement). Every admin section has edit and delete for every record type, guarded by a confirmation. Deletes cascade (a lead takes its activity and bookings; a project takes invoices, milestones, documents and approvals). The only guard rails: the last active owner can't be deleted, you can't deactivate yourself, Jamaica can't be removed as the launch country, and core pages can be unpublished but not deleted.
15. **Stage automation runs on every stage change** (drag and drop, drawer edit, or conversion): request deposit, send invoice, client approval, schedule install, request review. Failures are logged to the project activity instead of blocking the move.

## Phase 3 and 4

16. **Social publishing uses first-party APIs** (Meta Graph for Facebook and Instagram, LinkedIn, Pinterest, YouTube) with OAuth handled in `/api/social/start|callback/[network]` and tokens stored encrypted (AES-256-GCM, `SESSION_SECRET`-derived key). Without app credentials the UI still works: posts schedule, the calendar fills, and publishing marks the post failed with the reason.
17. **E-sign is built in** (typed name + timestamp + IP, PDF copy) with an optional Dropbox Sign adapter when `DROPBOX_SIGN_API_KEY` is set. Signed proposals emit `proposal.signed` and log to the lead and project.
18. **Stripe is optional.** With keys, "Send" creates a hosted Stripe invoice and the webhook marks it paid; without keys, invoices email as plain notices and are marked paid by hand.
19. **Client portal links are long random tokens** (`/portal/<token>`), issued on conversion (welcome email) or from the project drawer, revocable at any time. Clients see milestones, documents and invoices marked visible, and respond to approvals there.
20. **HubSpot sync is one-way** (leads → contacts, projects → deals) and no-ops until `HUBSPOT_ACCESS_TOKEN` exists.

## Notifications (SendGrid senders, Slack, texts through Call Flow Tracker)

21. **Four verified SendGrid senders, chosen per message** (owner's direction). `noreply@` for anything nobody answers (sign-in links, receipts, internal notices), `support@` for non-sales questions (Caribbean Connection submissions and moderation, portal, invoices), `consultation@` for everything sales-related (consultation requests, bookings, reminders, proposals, drips), `newsletter@` for newsletter mail. Consultation-form submissions are notified to the **consultation@** inbox, all other forms to **support@**; the inboxes are editable in the admin. Team notices go out from `noreply@` with Reply-To set to the visitor. The outbox stores the sender on every row so re-sends keep it. To change the mapping, edit the `from:` at the call site or the inbox in Form builder → Notifications.
22. **Texts to Grace go through Call Flow Tracker, not a second Twilio account.** CFT owns the Twilio connection and her tracking number, so this app signs in to CFT server-side (CFT's existing master-dashboard SSO, `/sso/launch?return=json`) and calls CFT's `POST /api/messages/send`, sending from `CFT_SMS_FROM`. The thread appears in CFT → Messages and replies land there. All SMS (lead confirmations and reminders too) take this route when configured; direct `TWILIO_*` keys remain a fallback, then the logged outbox. CFT needs `MASTER_DASHBOARD_SECRET` set; this app holds the same value as `CFT_MASTER_DASHBOARD_SECRET`.
23. **Auto sign-in into Call Flow Tracker is a revocable link, not a long-lived CFT token.** The texted link (`/go/cft/<token>`) is a random token stored hashed with a 24h expiry (`CFT_LAUNCH_LINK_HOURS`), bound to the notification user, audited on every tap and revoked when that person is deactivated. Each tap mints a fresh two-minute CFT token (CFT burns the `jti`, so re-taps still work). The same token format is reused for an "Open in Call Flow Tracker" button in the lead drawer, which signs in the *current* team member. CFT lands on its dashboard after SSO; deep-linking to `/calls` would need CFT to honour a `?next=` on `/sso/launch`.
24. **Slack via a single Incoming Webhook.** One `SLACK_WEBHOOK_URL`, Block Kit messages with action buttons, posted for consultation requests, other public forms and CFT call events, each a toggle in the admin. The auto sign-in link is included in Slack posts by default (toggle `cftLinkInSlack`), so the channel should be private.

## Caribbean Connection

25. **Community events stay listed through the end of their date, then leave at midnight in the event's own time zone.** An event row stores a start instant (noon on the chosen date) and a time zone, not an end time, so "its date is today or later" is the fairest reading of "still worth seeing": a workshop that began at 10 am is still relevant at 3 pm, and yesterday's is not relevant at 9 am. The rule is `isUpcomingEvent` in `src/lib/cc-events.ts`, shared by the public page and the admin count, and `npm run test:cc-events` pins it down. The public page renders per request, so nothing has to be cleared from a cache for an event to disappear. To cut off at the start time instead, change that one function; to honour a real end time, add an `ends_at` column first.

## Newsletter

26. **Insta-Newsletter is the newsletter system; the website only captures sign-ups and hands them over.** The owner's direction: nothing newsletter-shaped should be built or used in this app when Insta-Newsletter already does it. So designed newsletters are written and sent in Insta-Newsletter, every sign-up is pushed there through its public v1 API with an account-scoped API key (the Oct 31 plan assumed no such API existed; it shipped since), and a dedicated **Newsletter** section holds both lists, the hand-off status and the connection. At Grace's request the Caribbean Connection page keeps its *Newsletter subscribers* tab and the plain-text *Compose issue* for quick notes to that list: a convenience on the same list, not a second newsletter system. The website keeps its two subscriber tables as the capture log and a per-row hand-off status, because the forms, the welcome email and the checklist PDF still live here and the admin needs to see that each person arrived. Insta-Newsletter's rules are honoured rather than worked around: a person who unsubscribed there is not re-added on the website's say-so (they are emailed a confirmation link instead), and the website never sends newsletters of its own. Key storage follows the webhook-secret precedent: Replit Secrets when set, otherwise pasted in the admin and AES-encrypted with the session secret.
