Consultation funnel — how a lead flows

{{ f.n }}{{ f.title }}{{ f.desc }}
Source tracking

Every entry point passes a source_page (residential, aging-in-place, home, general…). The form maps it to a path via PAGE_TO_PATH, pre-selects it and asks the visitor to confirm. Both values are stored on the lead and drive "Leads by source page" and per-path filters. UTM parameters are captured alongside.

Admin-configurable questions

The form renders from form_fields rows, not hard-coded UI. Base fields appear on every path; path fields only for that audience. Admin adds, edits, reorders, requires or hides any field and picks wizard or single-page mode. Types: text, email, phone, select, multiselect, textarea, address, date, upload, consent.

Recommended stack & constraints

  • Next.js (App Router) + Supabase (Postgres, Auth, Storage, Row-Level Security for roles). Vercel hosting on graceindesign.net.
  • Content stored as structured page_blocks; public pages render from the database so the CMS is real, not a theme editor.
  • Email via Resend, SMS via Twilio, .ics generated server-side; cron for 24h reminders and RSS/Etsy sync.
  • Social publishing through Meta Graph API, LinkedIn, Pinterest and YouTube Data APIs (Phase 3); posts are scheduled as rows and dispatched by a worker.
  • Phase 4 integrations (HubSpot, Stripe, e-sign) are isolated behind an integrations table so they can be swapped.
  • Keep the existing Etsy shop as the storefront; the site only lists and links.
